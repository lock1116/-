## 数据库
1、mysql逻辑架构
分为上下两层，server层和存储引擎层
server层：所有存储引擎共用，负责连接管理、语法解析、查询优化、执行调度等。
连接器，管理客户端连接，身份认证，权限管理
分析器，语法和词法分析，生成解析树
优化器，生成执行计划，选择索引，决定表连接顺序
执行器，调用存储引擎接口，逐条/批量执行，返回结果
存储引擎层：负责数据的存储、读取、事务、锁、MVCC等。
采用插件式架构，表级别可独立指定引擎。
常见的存储引擎有innodb和myisam
2、InnoDB和MyISAM存储引擎的区别
InnoDB支持事务，使用的是聚簇索引，可以根据主键查询到数据，支持外键，支持表级锁和行级锁，锁的颗粒度更高；MyISAM不支持事务，使用的非聚簇索引，不支持外键，只支持表级锁。mysql5.7之后默认使用引擎为InnoDB
3、为什么mysql用B+树做索引？
因为随机读写磁盘的速度很慢，B+树是多叉树，一般树高只有2-4次，意味着查询一条记录只有2-4次磁盘i/o，二叉树和红黑树，树高可能会达到十几二十层，就要进行多次磁盘i/o，速度慢。
B+树将所有数据只存储到叶子节点上，且叶子节点中都是用双向链表串联，范围查询时，只要沿着链表遍历。B树的数据是随机存放，范围查询时，必须中序遍历树，导致多次磁盘i/o。
B+非叶子节点只存索引键（Key）和指针，不存具体数据。因此一个16KB的磁盘页能塞进更多索引项，进一步降低树的高度（变得更矮）。B树的每个节点都存数据，导致节点“臃肿”，树变高，I/O次数增加。
